# Simon Ledger 全链路协作、冲突处理与云端统计设计

- 日期：2026-08-21
- 状态：已完成产品确认与书面审阅，分阶段实施中
- 涉及仓库：`simon_ledger_flutter`、`simon-ledger-api`
- 不涉及仓库：`simon-ledger-admin`

## 1. 背景

Simon Ledger 当前采用本地优先架构：未登录用户可以在本机完整记账；登录后，Flutter 使用远端 Repository，但仍先写本地缓存，再异步上传 API。现有实现已经具备本地账本、云端账本、参与人、流水、邀请、成员角色、待同步状态和流水版本检查。

本次设计解决以下尚未闭环的问题：

1. 邀请加入只创建账本成员，没有保证登录用户同时成为可分摊的参与人。
2. Flutter 邀请固定为 `editor`，没有成员角色管理界面。
3. `editor` 可以编辑自己创建的流水，但后端不允许删除自己的流水。
4. 只有流水具备版本控制，账户资料、账本、成员和参与人仍可能发生最后写入覆盖。
5. 版本冲突只表现为同步失败，用户无法比较并选择本机或云端版本。
6. 云端账本的统计由 Flutter 本地计算，不能保证与服务器权威数据一致。
7. 本地账本和云端账本虽然已有状态字段，但产品上需要更明确地区分，且登录不能触发自动导入。

## 2. 目标

本次交付必须实现：

- 邀请加入后，账号自动拥有对应的账本参与人，可以被选择为分摊对象；默认 `editor` 可以记账。
- owner/admin 可以在 Flutter 中邀请成员和管理允许范围内的成员角色。
- `editor` 可以编辑、删除自己创建的流水，但不能操作他人的流水。
- 账户资料、账本、成员、参与人和流水全部使用乐观锁版本控制。
- 冲突采用非阻断、逐项、人工选择的处理模式。
- 云端账本统计以 API 为准；API 不可用时回退本地计算并明确提示。
- 本地账本不自动导入，保留显式导入入口，并在列表中明确显示账本类型。

## 3. 非目标

本次不包含：

- Admin 后台功能改造。
- 自定义分摊比例；收入和支出继续按参与人平均分摊。
- 与本需求无关的整体 UI 重做。
- 基于完整事件溯源的同步引擎重构。
- 自动合并冲突字段；所有真实数据冲突必须由用户明确选择。

## 4. 已确认的产品规则

### 4.1 成员与参与人

`Ledger Member` 表示账号对账本的访问权限，`Person` 表示分摊对象，两者继续保持独立。

通过邀请加入时，API 必须在同一事务内：

1. 校验邀请码可用性。
2. 创建或恢复 `ledger_member`。
3. 使用 `ledger_id + linked_user_id` 查询绑定该账号的 `ledger_person`。
4. 如果找到软删除记录，则恢复并同步账号昵称、头像；如果找到有效记录，则直接复用并同步资料；如果不存在，则创建新参与人。
5. 增加邀请码使用次数。
6. 返回邀请、账本、成员和参与人结果。

不能按昵称自动合并参与人，避免同名用户被错误绑定。成员被移除后，其参与人继续保留，以保证历史流水和分摊可解释；同一账号重新加入时复用原参与人。

### 4.2 角色权限

| 操作 | owner | admin | editor | viewer |
| --- | --- | --- | --- | --- |
| 查看账本、人员、流水和统计 | 是 | 是 | 是 | 是 |
| 修改账本设置 | 是 | 是 | 否 | 否 |
| 管理参与人 | 是 | 是 | 否 | 否 |
| 生成邀请 | 是 | 是 | 否 | 否 |
| 邀请 admin | 是 | 否 | 否 | 否 |
| 邀请 editor/viewer | 是 | 是 | 否 | 否 |
| 修改或移除 admin | 是 | 否 | 否 | 否 |
| 修改或移除 editor/viewer | 是 | 是 | 否 | 否 |
| 新增流水 | 是 | 是 | 是 | 否 |
| 编辑任意流水 | 是 | 是 | 否 | 否 |
| 删除任意流水 | 是 | 是 | 否 | 否 |
| 编辑自己创建的流水 | 是 | 是 | 是 | 否 |
| 删除自己创建的流水 | 是 | 是 | 是 | 否 |
| 删除整个账本 | 是 | 否 | 否 | 否 |
| 退出共享账本 | 否 | 是 | 是 | 是 |

owner 角色不可修改或移除。admin 不能创建、任命、降级或移除 admin。

### 4.3 账本导入和类型展示

- 登录不会自动上传本地账本。
- “我的 → 本地数据导入云端”继续作为唯一主动导入入口。
- 账本列表明确显示：`本地账本`、`云端账本`、`共享账本`。
- 待同步和同步失败是附加状态，不能替代账本类型。
- 本地账本导入成功后继续保留本地 UUID，通过 `syncedRemoteUuid` 关联云端 UUID。

## 5. 总体架构

采用实体级乐观锁和本地冲突快照：

```text
Flutter 写操作
  -> 先保存本地 pendingSync
  -> Repository 向 API 提交实体版本
  -> API 比较 version
      -> 一致：写入、version + 1、记录 change log
      -> 不一致：返回 409001 和云端完整快照
  -> Flutter ConflictCoordinator 保存本机/云端快照
  -> 当前实体停止自动重试，其他实体继续同步
  -> 用户在冲突中心逐项选择
      -> 使用云端：覆盖本地
      -> 保留本机：以云端最新 version 重新提交
```

不采用变更日志回放作为冲突恢复主机制。`ledger_change_log` 继续用于记录变更和后续增量查询，但本次冲突判断以实体 `version` 为准。

## 6. 数据模型

### 6.1 API 数据库版本字段

新增 SQL 迁移，为以下表增加非空版本字段：

```text
user_account.version            INT NOT NULL DEFAULT 1
ledger.version                  INT NOT NULL DEFAULT 1
ledger_member.version           INT NOT NULL DEFAULT 1
ledger_person.version           INT NOT NULL DEFAULT 1
ledger_transaction.version      已存在
```

每次成功更新、软删除或恢复都执行 `version = version + 1`。创建实体时版本为 1。

### 6.2 Flutter 模型

以下模型增加或统一暴露 `version`：

- `AuthUser`
- `LocalProfile` 的远端基准版本
- `Ledger`
- `LedgerMemberSummary` 或独立成员模型
- `Person`
- `TransactionRecord`

纯本地账本也维护本地版本，但不参与 API 冲突。导入云端时服务器新实体从版本 1 开始，本地记录保存远端版本和 UUID 映射。

### 6.3 本地冲突记录

Flutter 新增 `ConflictRecord`：

```text
id                   本地冲突 UUID
entityType           profile | ledger | member | person | transaction
ledgerUuid           账户资料冲突可为空
localUuid            本地实体 UUID
remoteUuid           云端实体 UUID
operation            update | delete | restore
baseVersion          本机写操作依据的版本
remoteVersion        检测冲突时的云端版本
localSnapshot        本机完整业务快照
remoteSnapshot       云端完整业务快照
remoteDeleted        云端是否已软删除
detectedAt           冲突发现时间
state                unresolved | queuedLocal | resolving | failed
error                解决冲突提交失败的可读错误
```

冲突使用独立存储键 `local_store.conflicts.v1`。快照不能包含密码、Token 或密码 hash；账户资料仅保存昵称、头像、账号 UUID 和版本。

同一实体再次产生冲突时替换未解决记录的云端快照，保留最新云端版本，不重复创建多个可见条目。

## 7. API 契约

### 7.1 普通更新和删除

所有可修改实体的更新或删除请求必须携带 `version`。服务端更新条件必须同时包含主键、未删除状态和版本，不能先查询后无条件更新。

成功响应返回递增后的新版本。创建请求继续使用 `Idempotency-Key` 或 `clientOperationId`，不进入版本冲突中心。

### 7.2 冲突响应

版本不一致统一返回 HTTP 409 和业务码 `409001`：

```json
{
  "code": 409001,
  "message": "数据已被其他设备修改",
  "data": {
    "entityType": "transaction",
    "entityUuid": "remote-uuid",
    "submittedVersion": 3,
    "remoteVersion": 4,
    "remoteDeleted": false,
    "remoteSnapshot": {}
  }
}
```

如果实体已软删除，API 仍要返回其最后版本和可用于比较的业务快照，不能只返回 404。

### 7.3 冲突解决请求

- 保留本机且云端实体有效：使用原更新或删除接口，携带冲突响应中的 `remoteVersion`。
- 接受云端：不发写请求，Flutter 直接应用云端快照；下一次刷新再次校验服务器状态。
- 本机修改、云端已删除、用户选择恢复：调用实体对应的 `restore` 接口，携带 `remoteVersion` 和本机业务数据。
- 本机删除、云端已更新、用户确认删除：再次调用删除接口，携带 `remoteVersion`。

如果解决过程中服务器版本再次变化，API 再次返回 `409001`，Flutter 更新原冲突记录并要求用户重新确认。

### 7.4 邀请加入响应

`POST /api/invites/{code}/join` 返回专用结果：

```text
invite
ledger
member
person
```

接口继续使用幂等键。重复调用时，如果成员和参与人已经存在，则返回现有有效关系，不重复增加人员；邀请码使用次数只在首次成功加入时增加。

### 7.5 邀请角色

邀请创建和重新生成接口继续接收 `role`：

- owner：允许 `admin`、`editor`、`viewer`。
- admin：允许 `editor`、`viewer`。
- 其他角色：403。

Flutter 默认选择 `editor`。

### 7.6 成员角色

成员角色修改和移除请求增加 `version`。服务端按第 4.2 节权限矩阵校验操作者和目标成员。

### 7.7 云端统计聚合接口

新增：

```text
GET /api/ledgers/{ledgerUuid}/stats/overview
```

查询参数：

```text
type                 0 支出，1 收入
from                 可选 ISO-8601 开始时间
to                   可选 ISO-8601 结束时间
displayCurrency      CNY 或账本基础币种
```

一次响应返回：

```text
totalAmount
transactionCount
averageAmount
categories[]
personBalances[]
settlements[]
sourceVersion        当前账本最新 change log 版本
generatedAt
```

API 使用同一次数据库统计过程生成所有模块，避免总额、分类和人员数据来自不同时间点。

## 8. Flutter 同步设计

### 8.1 结构化结果

Repository 和同步协调器使用结构化结果区分：

- `success`
- `networkFailure`
- `permissionFailure`
- `authFailure`
- `conflict`

不能通过匹配错误文案识别冲突。

### 8.2 ConflictCoordinator

`ConflictCoordinator` 负责：

1. 把 API `409001` 和本地待同步实体组合为 `ConflictRecord`。
2. 持久化冲突并刷新全局、账本级冲突数量。
3. 阻止该实体继续自动重试。
4. 处理“使用云端”和“保留本机”。
5. 解决成功后删除冲突记录、更新实体版本并触发统计刷新。

冲突不会阻塞同一账本的其他实体，也不会阻塞其他账本。

### 8.3 同步顺序

继续保持：

```text
账户资料（独立）
账本 -> 成员/参与人 -> 流水
```

成员和参与人之间没有强制一一对应；只有受邀账号会自动获得绑定参与人。

### 8.4 错误处理

- 网络错误：保留 `pendingSync`，按现有生命周期和网络恢复机制重试。
- 权限错误：停止该操作自动重试，刷新账本和成员权限，并向用户说明权限已变化。
- 认证失效：保留全部本机数据，清理 Token，要求重新登录。
- 冲突：写入冲突中心，不继续自动重试。
- 普通校验错误：保留本机草稿或回滚界面乐观状态，显示具体字段错误。

## 9. Flutter UI 设计

### 9.1 冲突入口

冲突不立即弹窗打断当前记账。入口包括：

- App 顶部提示：“有 N 项数据需要确认”。
- 账本卡片的冲突徽标和数量。
- “我的 → 同步中心 → 数据冲突”。

手动同步完成后如果发现冲突，显示非阻断提示并提供“去处理”操作。

### 9.2 冲突中心列表

- 按账本分组，账户资料单独分组。
- 每项展示实体类型、名称、发现时间和变更摘要。
- 按发现时间从旧到新处理，保证依赖实体先得到确认。
- 每项只有一个明确的“查看差异”入口。

### 9.3 逐项对比

移动端上下排列本机和云端版本，只突出不同字段，相同字段默认折叠。

比较字段：

- 账户资料：昵称、头像。
- 账本：名称、基础币种、汇率。
- 成员：昵称标识、角色、成员状态。
- 参与人：名称、头像、绑定账号、删除状态。
- 流水：收支类型、金额、币种、分类、时间、垫付人、参与人、备注、删除状态。

底部固定两个操作：

- `保留本机版本`
- `使用云端版本`

不提供批量覆盖。处理完成自动进入下一项并显示剩余数量。

覆盖或删除云端属于破坏性选择，需要二次确认；普通字段接受本机或云端不重复弹窗。

### 9.4 离线处理

- 离线时可以查看全部已保存冲突。
- 选择云端版本可以立即应用冲突记录中的云端快照。
- 选择本机版本进入 `queuedLocal`，显示“等待联网提交”。
- 联网后自动提交；如果再次冲突，回到 `unresolved` 并更新差异。

### 9.5 账本编辑和成员管理

账本编辑页分为：

1. 账本设置：名称、币种、汇率。
2. 共享成员：账号访问权限、角色和移除操作。
3. 参与人：分摊对象和手动人员。

owner 行显示固定标识，不提供角色菜单。admin 查看其他 admin 时不显示编辑或移除操作。

### 9.6 邀请角色选择

邀请生成页在有效期和使用次数之前显示角色选择：

- owner：管理员、可共同记账、仅查看。
- admin：可共同记账、仅查看。
- 默认：可共同记账（`editor`）。

角色旁显示权限摘要，重新生成邀请码会使旧邀请码失效。

### 9.7 流水操作可见性

- owner/admin：所有流水显示编辑和删除。
- editor：只有自己创建的流水显示编辑和删除。
- viewer：不显示新增、编辑和删除入口。

前端隐藏只是体验控制，API 始终执行最终权限校验。

### 9.8 账本类型

账本卡片使用稳定标签：

- `本地账本`
- `云端账本`
- `共享账本`

另行显示 `待同步 N 项`、`同步失败 N 项` 或 `冲突 N 项`。本地账本登录后仍保持本地类型，只有用户主动导入成功后才转为云端账本。

## 10. 云端统计和本地回退

### 10.1 数据来源

- 本地账本：使用 Flutter 本地统计计算器。
- 云端账本且 API 可用：使用 `/stats/overview`。
- 云端账本且 API 不可用：使用本地缓存流水计算。

云端账本存在待同步流水时，在线统计仍以 API 为准，并提示：“有 N 条待同步记录，当前云端统计暂未包含”。

### 10.2 离线展示

API 失败时显示：

- `离线统计` 标识。
- 上次云端统计成功时间。
- 本地待同步记录数量。

离线计算包含本机待同步流水。API 恢复后自动重新请求并切回云端结果。

### 10.3 共享数据层

账本详情与“统计”主页面共用同一统计 Repository、筛选模型和缓存，不能分别实现两套口径。

缓存键至少包含：

```text
ledgerUuid + transactionType + from + to + displayCurrency
```

同步完成、解决冲突、修改汇率或切换筛选后使相关缓存失效。

## 11. 数据库和本地迁移

API 新增独立 SQL 迁移文件，不修改已发布迁移：

- 为 `user_account`、`ledger`、`ledger_member`、`ledger_person` 增加版本字段。
- 保持现有软删除字段和唯一键。
- 为受邀用户参与人复用查询补充适当索引；不能增加会阻止历史软删除记录存在的错误唯一约束。

Flutter 读取旧缓存时：

- 缺少远端版本按 1 读取。
- 下一次云端刷新用 API 版本覆盖。
- 如果版本假设过期，首次提交进入正常冲突流程。
- 不删除现有账本、参与人或流水缓存。

### 12.4 端到端场景

至少验证：

1. 两台设备同时编辑同一流水，后提交设备进入冲突中心。
2. 一台设备编辑、另一台设备删除同一流水，双方都能得到正确选择。
3. 两台设备同时修改账本汇率、参与人和账户资料。
4. editor 编辑和删除自己的流水，无法操作他人流水。
5. owner 邀请 admin，admin 只能邀请 editor/viewer。
6. 被移除成员重新加入并复用原参与人。
7. 登录后本地账本不自动上传，主动导入后完成 UUID 映射。
8. API 不可用时云端账本显示离线统计，恢复后切回云端统计。

## 13. 验收标准

以下条件全部满足才视为完成：

- Flutter 和 API 对五类可修改实体使用统一版本控制。
- 冲突不会阻断正常记账或其他实体同步。
- 用户必须逐项明确选择本机或云端，没有静默覆盖。
- 删除与恢复冲突拥有准确文案和服务端支持。
- 邀请加入后用户立即出现在参与人列表，可被分摊；默认 editor 可以记账。
- 成员角色邀请、编辑和移除严格符合权限矩阵。
- editor 可以删除自己创建的流水，不能删除他人流水。
- 登录不会自动导入本地账本，账本类型始终清晰可见。
- 云端账本在线统计来自 API，离线时明确回退本地。
- 相关 Flutter、API 和端到端测试通过。

## 14. 分阶段交付顺序

本设计作为一个产品闭环验收，但实施必须拆分为可独立验证的阶段：

1. **API 并发基础**：数据库版本迁移、五类实体版本校验、结构化冲突响应、软删除恢复能力和权限测试。
2. **Flutter 冲突基础**：版本模型、本地迁移、`ConflictStore`、结构化同步结果和 `ConflictCoordinator`。
3. **冲突 UI**：全局入口、账本徽标、逐项差异、离线选择和删除/恢复确认。
4. **协作闭环**：邀请角色选择、成员管理、editor 自有流水删除、加入后参与人自动创建或复用。
5. **统计权威链路**：API 聚合统计、Flutter 云端统计 Repository、本地回退和双页面统一口径。
6. **全链路验证**：双设备并发、离线恢复、权限变化、本地账本导入和统计切换场景。

每个阶段都必须保持 Flutter 与 API 的接口契约一致，并在进入下一阶段前运行对应测试。阶段拆分用于降低交付风险，不改变第 13 节的整体验收标准。
