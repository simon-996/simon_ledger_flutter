# 账号隔离与离线账本认领设计

日期：2026-09-22
状态：设计已确认，待实施

## 1. 目标

解决同一设备切换账号后出现的本地数据串号问题，同时保留离线记账能力：

- 未登录创建的本地账本没有账号归属，登录前后都可以查看。
- 用户主动同步后，整本账本归属当前账号。
- 已归属账号的账本在退出登录后隐藏，其他账号不能看到。
- 共享账本仍由服务端成员关系控制，成员看到的是同一份账本和人员数据。
- 当前登录用户的资料变化不能改写其他人员或其他账号的本地缓存。

## 2. 现状与问题

当前 Flutter 本地存储使用全局的 SharedPreferences key 保存账本、人员和交易，没有账号命名空间。账本虽然已经有 `cacheOwnerUserUuid`，但人员、交易和身份映射仍然与设备全局缓存混合。

此外，当前用户投影逻辑会使用 `self`、旧昵称或旧头像识别本地人员。账号切换后，这些条件可能命中上一个账号的缓存，从而把 A 的人员名称和头像改成 B 的资料。

账本列表还采用先展示缓存、再异步刷新远端的策略。如果缓存没有按账号隔离，B 会在刷新完成前看到 A 的旧账本。

服务端 `/api/ledgers` 已经按当前账号的有效成员关系返回账本，因此云端访问控制继续以服务端为准；本次设计重点是 Flutter 本地缓存、账号上下文和同步认领流程。

## 3. 数据归属模型

本地数据分为两个空间，云端访问再单独由服务端控制。

### 3.1 游客本地空间

游客空间使用固定的 `guest` scope：

- 账本、人员、交易均没有账号归属。
- 未登录时显示。
- 登录后仍显示，并明确标记为“本地账本 · 尚未同步”。
- 同一设备上的不同账号都可以看到这些未归属数据，这是有意保留的设备级离线行为。
- 任何账号都可以主动认领并同步，但必须经过明确操作和确认。

### 3.2 账号空间

账号空间使用 `account/<accountUuid>` scope：

- 仅保存该账号创建、认领或缓存的账号数据。
- 登录该账号时显示。
- 退出该账号后隐藏。
- 其他账号不能通过本地缓存读取。
- 重新登录原账号后恢复显示。

账号空间中的云端共享账本仍然需要满足服务端成员权限。B 只有成为共享账本成员后，才会在 B 的账号空间缓存该账本。

### 3.3 可见性规则

| 当前状态 | 可见数据 |
| --- | --- |
| 未登录 | `guest` 空间的本地账本 |
| 登录 A | `guest` 空间 + A 的账号空间 + A 已加入的共享账本 |
| 登录 B | `guest` 空间 + B 的账号空间 + B 已加入的共享账本 |
| 登录 A 查看 B 的账号数据 | 不可见 |
| 未登录查看已归属账号的账本 | 不可见 |

## 4. 本地存储设计

优先采用按 scope 分开存储，而不是只给现有对象增加一个可选字段。这样可以让数据库查询默认带上当前 scope，降低遗漏过滤条件导致数据串号的风险。

建议的存储结构：

```text
local_store.guest.people.v2
local_store.guest.ledgers.v2
local_store.guest.transactions.v2

local_store.account.<accountUuid>.people.v2
local_store.account.<accountUuid>.ledgers.v2
local_store.account.<accountUuid>.transactions.v2
local_store.account.<accountUuid>.conflicts.v2
```

`DatabaseService` 需要接收当前 `LocalDataScope`，所有读写方法都只能访问该 scope。scope 切换时必须重新创建或切换对应的 repository，不允许复用上一个账号的缓存结果。

本地资料也要区分游客资料和账号资料：

- 游客资料只用于游客空间的本地人员显示。
- 账号资料按 `accountUuid` 保存。
- 账号资料更新只能更新当前账号空间内明确关联当前用户的人员。
- 不能通过昵称或头像匹配人员。

## 5. 账本生命周期

账本状态如下：

```text
guest-local
    ↓ 用户点击“同步到当前账号”
claiming(account A)
    ↓ 远端账本、人员、交易完成同步
account-owned(account A)
    ↓ 邀请其他用户并被接受
shared(remote member access)
```

### 5.1 未同步本地账本

在游客空间创建或编辑的账本始终保留在 `guest` scope。登录后可以继续编辑，但保存仍然是本地操作，不会因为登录自动上传或自动归属当前账号。

界面需要显示未同步状态，并提供“同步到当前账号”入口。

### 5.2 认领与同步

用户点击同步时：

1. 必须存在有效登录账号。
2. 展示确认信息，说明同步后账本将归属当前账号，其他账号将无法继续看到该账本。
3. 将账本标记为 `claiming`，记录目标 `accountUuid`，防止用户退出后被其他账号认领。
4. 上传账本、人员和交易；每一步使用稳定的幂等 key，可以在网络失败后重试。
5. 全部完成后，将本地数据从 `guest` scope 迁移到目标账号 scope，并保存远端 UUID 映射。
6. 清除认领状态，账本显示为账号账本或云端账本。

同步过程中如果失败：

- 不把账本交给新登录的其他账号。
- 保留本地数据和 `claiming(account A)` 状态。
- A 再次登录后可以继续同步或取消认领。
- 只有明确取消认领后，账本才回到 `guest` scope。
- 远端已经创建的部分使用幂等重试继续完成，不重复创建。

这是一种客户端可恢复的逻辑原子认领：用户界面只有在整本账本同步完成后才显示“已同步”，而网络中断不会导致数据被 B 看到或重复创建。

### 5.3 退出登录

退出登录时：

- 停止当前账号的刷新任务。
- 保留当前账号 scope 的本地缓存和未完成同步任务，但不再展示。
- 清空内存中的账号相关 provider 状态。
- 切换到未登录状态后，只显示 `guest` scope。
- `account-owned` 和 `claiming(account A)` 数据都不可见。

如果当前账号有未完成同步，退出前应提示用户“同步尚未完成”，允许继续退出，但明确说明下次登录该账号后可继续。

## 6. 人员与身份规则

人员的身份匹配只能使用以下稳定身份：

- 本地人员 UUID。
- 远端人员 UUID。
- `linkedUserUuid`。
- 当前账号 UUID。

昵称和头像只属于展示信息，不能用于判断两个人员是否是同一个人。

未同步本地账本中的“自己”也是普通本地人员，登录后不能自动改名为当前账号的昵称。用户认领账本时可以显式选择“将本地自己关联为当前账号”，这会写入 `linkedUserUuid`；未选择时保留原有人员名称。

共享账本从服务端刷新人员时，以远端人员 UUID 为准。B 加入 A 的共享账本后，看到的是账本中已有的人员；B 只有在显式新增或关联人员时，才会出现 B 的人员信息。

## 7. 旧数据迁移

升级到新存储结构时执行一次迁移：

1. 已有 `cacheOwnerUserUuid` 且能确认账号的云端账本，迁移到对应账号 scope。
2. 已有本地临时账本、未同步账本和无法确认归属的记录，迁移到 `guest` scope。
3. 人员和交易按照其关联账本迁移。
4. 无法关联账本的人员、交易或冲突记录放入 guest scope，不能默认归给当前登录账号。
5. 不执行基于昵称、头像的自动归属或重命名。
6. 迁移完成后保留版本标记，避免重复迁移。

如果旧缓存中的远端账本没有账号归属信息，先隐藏该缓存，随后通过当前账号的服务端账本列表重新建立归属；不能仅凭设备上残留的数据把它归给当前账号。

## 8. 服务端边界

现有服务端账本列表和成员权限可以继续作为云端访问控制。Flutter 需要保证：

- 不把本地缓存当作云端权限。
- 不因本地缓存命中就绕过 `/api/ledgers` 的成员过滤。
- 账本认领上传继续使用幂等 key。
- 已经存在的创建账本、创建人员和交易同步接口可以先复用；如果后续需要真正的服务端单事务导入，再增加批量认领接口。

## 9. 测试验收标准

### 本地隔离

- 未登录创建的账本，未登录时可见。
- 登录 A 后，未同步账本仍可见并标记为未同步。
- 登录 B 后，未同步账本仍可见，但 A 已同步的账本不可见。
- A 重新登录后，A 的已同步账本恢复显示。
- 退出登录后，任何账号账本都不可见，只显示 guest 空间。

### 同步认领

- guest 账本同步到 A 后，账本、人员和交易全部进入 A 的 scope。
- A 退出后该账本不可见，B 登录后也不可见。
- 同步失败可以重试，不产生重复远端账本、人员或交易。
- A 认领过程中退出，B 不能接管；A 再登录后可以继续或取消。
- 取消认领后，账本回到 guest scope。

### 身份与共享

- B 加入共享账本后，原有人员名称、头像和 UUID 不被替换。
- 修改账号昵称或头像不会修改其他人员。
- 同昵称、同头像但不同账号不会被识别为同一人员。
- 共享账本仍然只对服务端有效成员可见。

### 迁移

- 已知账号归属的旧缓存迁移到对应账号空间。
- 无法确认归属的旧缓存进入 guest 空间。
- 迁移重复执行不会产生重复账本、人员或交易。

## 10. 实施边界

第一阶段只实现本设计涉及的本地 scope、账号切换、认领同步和身份匹配修正，不调整账本业务权限、邀请角色或交易冲突算法。服务端只在现有接口无法支持幂等恢复时补充最小接口。
