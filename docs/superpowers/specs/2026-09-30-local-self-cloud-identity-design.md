# 本地本人同步为云账号人员

用户于 2026-09-30 确认：本地账本内系统创建的 self，在用户主动上传账本时转为当前云账号对应的记账人员；普通人员保留原有身份和资料。

## 身份和展示

- Person 保存明确的本地本人标记；兼容旧版系统 UUID `self`、`p1` 和 `self-<时间戳>`，包括登录后生成的 `guest:` 前缀。昵称或头像不用于身份识别。
- 认领时仅本人关联当前账号，并使用该账号资料。共享成员权限和记账人员保留各自记录，通过 linkedUserUuid 关联；列表仅展示一次，记账仍使用人员 UUID。
- 账号资料更新仅更新明确关联该账号的人员。游客资料仅更新明确的游客本人。

## 引用和隔离

- 本地人员 ID 可以被多个游客账本引用。认领时复制人员，不修改剩余游客记录；如果其他账本仍引用该人员或目标账号存在同 UUID，给认领副本生成稳定的账本专属 UUID。
- 同时迁移被认领账本和全部历史交易内的参与人、付款人引用，其他账本引用不变。
- 每个账本的人员副本各自保存云端映射，后续上传不能覆盖其他账本的映射。
- 网络失败保留已认领人员和引用，沿用现有幂等 key 重试。

## 已上传数据

- 同步时检查仍有明确本地 self 标记、云端映射且尚未关联账号的人员；核实远端人员属于该账本后，通过现有人员更新接口关联本人。
- 同名普通人员不修复。远端已经关联其他账号时不覆盖；没有可核实的映射时保留数据。
- 无需服务端数据库结构变化。

## 验证

回归测试覆盖：本人与同名普通人员、账号资料修改、两个账本共享人员、交易付款人及历史参与人引用、已有上传账本的身份修复、失败重试和单次显示。运行相关 Flutter 测试和静态分析。
