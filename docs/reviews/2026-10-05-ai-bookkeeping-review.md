# AI 记账代码复核与功能验证

日期：2026-10-05。复核范围：API v2 语义校验、旧协议兼容、Flutter 摘要与详细复核、草稿持久化及交易保存链路。

## 结论

复核发现了可以复现的识别和复核问题，已在两个 `feat/ai-bookkeeping` 工作树中修正。新增回归测试先验证失败，再验证修复；最终后端完整测试与 Flutter 完整测试通过。当前结果证明本地规则、协议和交互在测试场景下正确，真实供应商的识别准确率仍待测量。

## 已修正的问题

| 场景 | 原行为与影响 | 修复与验证 |
| --- | --- | --- |
| 原文金额 `1400`、`400.50`、`1,400`、`一千四百`，模型仅提取 `400` / `四百` | 子串也能作为金额证据，可能少记金额 | 校验完整数字边界，拒绝局部数字；对应回归用例通过 |
| `400美元`、`400欧元`、`400日元` 等 | 外币名称中的“元”被同时识别为 CNY；日元中的“日”又可能被当作日期单位 | 外币名称先独立识别，再判断普通“元”；日元单位允许作为金额后缀；九种币种回归通过 |
| `我和李四都住，李四垫付`、`我们先付`、`张三没垫付`、`不是张三付` | 可能错误匹配本人或被否定的付款人 | 要求付款证据对应实际角色，处理复数“我们”和否定语句；没有明确付款人时进入复核 |
| `不是所有人都住` | 包含“所有人”就可能套用全体范围 | 否定全体不能作为 ALL 的正面证据，生成待核对问题 |
| 模型返回重复条目或倒序原文片段 | 同一笔可能生成重复草稿，或顺序与输入不一致 | 来源片段必须按输入顺序出现且互不重叠；有效多笔保留 |
| `18:00` 被返回为 `08:00`，`18点30分`丢失分钟，`下午8点`返回上午，或凭空增加秒数 | 时间子串或局部证据被接受 | 校验完整时刻、时段与分钟；缺失/矛盾时刻产生日期问题；明确 `00:00` 保留 TIME 精度 |
| 当前账本只支持 CNY，草稿 CNY 存在币种冲突 | 选择同一个币种不触发事件，用户无法解除阻塞 | 提供显式“确认币种”操作，保持金额数值，清除币种问题并标记 USER |
| 需排除的姓名不在账本中 | 只能选择其他人排除，缺少保留当前名单的出口 | 增加“取消这项排除，保留当前名单”，按用户确认保留人员快照 |
| 修改金额为 `400.123`，或打开同样金额的旧草稿 | 摘要显示两位小数但可能保存更多小数；详细表单又可能静默四舍五入 | 共享校验最多两位小数；保留异常原值；摘要显示“金额待核对”；修正前阻止保存 |
| 用户修改金额 | 字段来源没有标记为用户修正 | 修改金额清除该字段问题并设置 `fieldSources.amount = USER`，保存回归通过 |

额外修正了中文界面测试使用旧文案“谁付款”的定位；现在验证“付款方式”、个人垫付和共同钱包控件，以及金额错误提示在键盘出现后仍可见。

## 尚未验证的部分

- 当前测试进程未配置 `DEEPSEEK_API_KEY`，没有执行真实供应商请求，也没有完成计划中的 60 条语料各三次、共 180 次模型评测。合成 fixture 和 mock 结果不能当作真实模型准确率。
- 没有进行真实服务器、数据库、设备录音和网络环境的端到端联调；语音上传、权限及失败分支通过现有自动化测试验证。
- 六项 MySQL 集成测试的环境条件未满足；未执行生产部署。

供应商客户端使用的 Responses API 协议已对照官方资料核验：[创建 Responses 请求](https://api-docs.deepseek.com/api/create-response/)、[Responses API 指南](https://api-docs.deepseek.com/guides/responses_api/)。这项资料核验不替代实际网络调用。

下一步应在具备供应商测试凭据的环境执行真实模型评测，重点观察完整字段匹配率、错误预填率和需要人工补充的字段；根据结果调整语义提取提示和规则，再进行端到端验收。

## 远端更新合并验证（2026-10-05）

已拉取 API `origin/master` 到 `398280a`、Flutter `origin/master` 到 `152f494`，两边本地 `master` 快进到对应提交。两个 AI 改造工作树合入这些远端更新，解决 API 四个文件和 Flutter 八个文件的文本冲突，并复核自动合并的字段与调用路径。

合并保留的关键行为：

- API 按 schemaVersion 分流：v1 使用远端分类上下文、权威人员过滤和近似匹配；v2 使用参考日期、语义提取及确定性校验。两条路径共享供应商安全诊断。
- Flutter 内部统一付款模式，接受旧枚举及 v1 小写协议值；v1 序列化保留旧格式，v2 序列化保留大写语义格式及全部字段。
- 云端人员 UUID 映射为本机账本人员 UUID，同时保留 v2 的版本、字段来源、问题、日期精度及参考日期，并映射问题中的候选身份；新增回归验证幂等性。
- 保留近似匹配来源提示、遗留姓名先确认角色、恢复失败重试、云端交易先创建后更新身份，以及账本摘要按类型筛选的修复。
- 保留远端移除语音和关闭确认弹窗的交互，关闭仍等待草稿和输入持久化；旧测试更新后继续验证保存与恢复。
- 保留小时分钟控件。新增失败用例复现了手动改时刻后仍保留 DAY 精度的问题，修复后使用 TIME 精度，摘要能够显示所选时刻。
