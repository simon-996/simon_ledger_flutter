# 滑动交互复核与修复

## 范围

用户反馈滑动不够流畅，按手机优先检查记账、账本、流水和统计页的共享交互组件。此次修复以 `ad7f43a` 为基础，不涉及后端或数据结构。

## 复现与原因

1. `AppPressable` 只在指针按下、松开和取消时改变缩放状态，没有处理拖动。实际流水卡片中，纵向拖动已开始后仍保持 `0.985` 的按压缩放；直接组件中拖动再返回起点也仍保持 `0.975`。这是可复现的视觉抖动原因，不能据此推断帧率。
2. `AppAnimatedEntry` 在每次挂载时执行延迟淡入、位移和缩放。流水、账本和人员列表采用惰性构建，新条目在滚动时挂载，也会等待入场动画。零缓存的 ListView 与 SliverList 测试中，新可见条目的首帧透明度均为 `0`。
3. 统计页和账本详情中的横向人员列表位于纵向滚动页面内。只观察最近一个 Scrollable 会漏掉外层纵向滚动，此情况也已通过单独测试复现。

最初 6 项专项测试在旧实现中出现 5 项预期失败，静止页面入场测试通过；补充的嵌套滚动测试在单轴监听实现中出现预期失败。

## 修复

- 按压反馈跟踪触发它的主按钮指针，使用 Flutter 的设备类型与 gestureSettings 计算移动容差。超过容差后恢复缩放，同一次手势返回原位时也不重新触发按压；保持原有点击识别与列表滚动手势。
- 入场动画同时观察最近的纵向和横向滚动状态。开始拖动或惯性滚动时结束待执行和未完成的动画，滚动中新建条目直接显示，保持静止页面首次打开时的动效。
- 动画完成后解绑滚动监听，销毁时取消延迟 Timer 并解绑；减少动态效果模式直接显示内容。

## 验证

- `flutter test --no-pub --reporter expanded`：447 项通过，其中新增 7 项滑动回归测试。
- `flutter analyze --no-pub`：无问题。
- `flutter build web --release --no-pub`：成功，输出 `build/web`。
- `git diff --check`：通过。
- 锁定版本的依赖已恢复，本次不变更依赖版本；插件自动生成文件不包含在提交中。

专项测试覆盖真实流水卡片拖动不误打开、拖动后返回起点、ListView 与 SliverList 新条目首帧显示、拖动结束待入场动画、纵横嵌套滚动，以及静止页面保留入场动画。

独立代码复核未发现阻断问题。复核补充检查了待执行动画卸载、拖动中重挂载、运行中的动画结束、ScrollPosition 替换、减少动态效果开关和自定义手势容差等生命周期与边界场景。

## 性能结论的边界

当前可用设备为 Windows、Chrome 和 Edge，未连接 Android 或 iOS 真机。这里验证的是交互状态和发布版构建，没有取得真机帧耗时、掉帧率或 60/120 FPS 数据，也没有证明用户遇到的所有卡顿均已消失。

后续若仍有卡顿，应依据具体页面、机型和数据规模，在真机 profile 模式记录慢速拖动、快速惯性滚动和返回滚动的帧耗时，区分 UI 构建与栅格绘制成本。调试预览不能作为发布版性能结论，参见 [Flutter 官方性能分析说明](https://docs.flutter.dev/perf/ui-performance)。
